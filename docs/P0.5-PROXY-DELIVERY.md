# P0.5 — Proxy Delivery: ContentDeliveryKind + wdmm_proxy_register_stream

**Branch:** `feat/proxy-hls-ffmpeg`

**Status:** ✅ Complete (worktree only, not pushed)

## Overview

P0.5 adds two things that were blocked after Round 12:

1. **`ContentDeliveryKind`** on `CloudFileItem` — a discriminant that tells
   callers how to obtain bytes from a driver item (network URL, local file,
   or in-process stream). This was previously documented as "Planned" in
   `docs/API.md`.

2. **`wdmm_proxy_register_stream` FFI** — exposes `ProxyHandle::register_driver`
   as a C ABI so Dart/Flutter can route `LocalStream` items through the local
   HTTP proxy (MustProxy path, crypt-wrapper driver output, etc.).

---

## 1. ContentDeliveryKind (`crates/wdmm-drivers`)

### New type

```rust
#[non_exhaustive]
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ContentDeliveryKind {
    NetworkDirect, // raw_url + raw_headers available
    LocalStream,   // in-process stream only — use proxy
    LocalFile,     // local_path is directly readable
}
```

### New field on `CloudFileItem`

```rust
pub struct CloudFileItem {
    // ...existing fields...
    pub delivery: ContentDeliveryKind,
    pub local_path: Option<std::path::PathBuf>,
}
```

### Constructors

```rust
CloudFileItem::network_direct(name, is_dir, size, modified, raw_url, raw_headers) -> Self
CloudFileItem::local_stream(name, is_dir, size, modified) -> Self
CloudFileItem::local_file(name, is_dir, size, modified, local_path) -> Self
```

### `ContentDeliveryKind::infer`

```rust
pub fn infer(raw_url: Option<&str>, local_path: Option<&Path>) -> Self
```

Priority: `NetworkDirect` > `LocalFile` > `LocalStream`. Exists to ease
migration of existing struct literals; prefer explicit construction at new sites.

### Driver migrations

All production drivers updated to use constructors instead of struct literals:

| Driver | Method | Constructor used |
|--------|--------|-----------------|
| `WebDavDriver` | `list`, `get` | `network_direct` |
| `CtFileDriver` | `list`, `get` | `network_direct` |
| `BaiduDriver` | `list`, `get` | `network_direct` |
| `Pan123Driver` | `list`, `get` | `network_direct` |
| `AliyunDriver` | `list`, `get` | `network_direct` |
| `Open115Driver` | `list`, `get` | `network_direct` |

Stub drivers (`TeraboxDriver`, `NeteaseMusicDriver`) return errors from all
methods — they never construct `CloudFileItem` instances, so no migration needed.

## 2. wdmm_proxy_register_stream (`crates/wdmm-ffi`)

### C callback type

```c
typedef int32_t (*WdmmProxyRangeCallback)(
    void*    user_data,
    int64_t  start,       // inclusive byte offset
    int64_t  end,         // inclusive end; -1 = to EOF
    uint8_t** out_buf,    // set to wdmm_proxy_stream_alloc_buf(n) output
    size_t*  out_len
);
// return 0 = success; negative = error
```

### New FFI exports

| Function | Purpose |
|----------|---------|
| `wdmm_proxy_register_stream(size, name, cb, user_data)` | Register in-process stream |
| `wdmm_proxy_renew_stream_callback(token, cb, user_data)` | Replace callback after key rotation |
| `wdmm_proxy_stream_alloc_buf(len)` | Allocate callback output buffer (Rust heap) |
| `wdmm_proxy_stream_free_buf(buf, len)` | Free buffer (for C error paths) |

### How it fits the LocalStream path

```
CloudFileItem { delivery: LocalStream, raw_url: None, local_path: None }
       │
       ▼
Dart / C caller:
  wdmm_proxy_start(0)            // start proxy once
  wdmm_proxy_register_stream(    // register item
      size, "movie.mkv",
      my_range_cb, ctx_ptr
  )                              → {"token":"…","path_template":"/s/…","port":N}
       │
       ▼ compose URL
  http://127.0.0.1:{N}/s/{token}
       │
       ▼ media_kit plays
  proxy receives GET / Range → invokes my_range_cb(ctx_ptr, start, end, …)
```

### Thread-safety contract

- `cb` and `user_data` must remain callable from any thread for the full
  lifetime of the registration (between `register_stream` and `unregister` /
  proxy stop).
- For async decrypt (Dart isolate → `openContentRange`): bridge with
  `NativeCallable.listener` — Dart side enqueues and signals; C callback
  blocks until Dart replies.

## 3. wdmm-sync updates

`wdmm-sync` consumed `CloudFileItem` fields directly. Updated where needed:
`delivery` field is available; the sync engine's `get_content` path is
unaffected (it calls `driver.get_content()`, not `.raw_url`).
